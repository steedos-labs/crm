# 通用验收清单

## 验收原则

每个 AI 开发任务必须先完成自检，再进入人工验收。验收不仅检查文件是否生成，还要检查业务能力是否可用、命名是否合规、权限是否明确、文档是否同步。

## 基础验收

- [ ] 任务范围与 `docs/design.md` 一致。
- [ ] 任务状态已在 `docs/project-management/tasks.md` 中更新。
- [ ] 所有新增或修改文档均使用中文。
- [ ] 未提交 `.env`、密钥、令牌或本地私有配置。
- [ ] 未引入不必要的新依赖。
- [ ] 未修改与当前任务无关的文件。

## Steedos 对象验收

- [ ] 所有自定义业务对象 API 名均以 `crm_` 开头。
- [ ] 每个对象都有 `.object.yml` 文件。
- [ ] 每个对象都有名称字段，或有一个字段设置 `is_name: true`。
- [ ] 每个对象都有必要字段，并使用中文 `label`。
- [ ] 每个对象都有至少一个 `.permission.yml` 文件。
- [ ] 每个对象都有至少一个 `.listview.yml` 文件。
- [ ] 关键查询字段已按需配置 `index: true` 或 `searchable: true`。
- [ ] 重要业务对象按需启用审计、附件、API、回收站等能力。

## 应用和导航验收

- [ ] CRM 应用文件存在，并设置 `showSidebar: true`。
- [ ] CRM 应用 `tabs` 数组包含本任务新增功能。
- [ ] 相关页签可以从侧边栏访问。
- [ ] 页签名称、图标和中文标签符合业务含义。
- [ ] 不存在无法从应用导航访问的孤立核心对象。

## 权限验收

- [ ] 管理员拥有必要的全部管理权限。
- [ ] 销售、服务、财务等角色的权限符合设计。
- [ ] 普通用户没有获得不应拥有的删除或全量修改权限。
- [ ] 敏感字段按需配置字段级权限。
- [ ] 页签可见性与对象权限保持一致。

## 业务流程验收

- [ ] 可以创建、查看、编辑核心业务记录。
- [ ] lookup 或 master-detail 关系指向正确对象。
- [ ] 列表视图字段可支持常见业务查询。
- [ ] 自动编号、状态、金额、日期等关键字段符合业务规则。
- [ ] 如涉及按钮、function 或 trigger，错误信息清晰，不存在静默失败。

## 文档验收

- [ ] `README.md` 或相关文档已按需更新。
- [ ] `docs/design.md` 已同步新的对象、字段、流程或权限变化。
- [ ] `docs/project-management/change-log.md` 已记录重要设计变更。
- [ ] 任务验收结果已记录在对应阶段文档中。

## 验证命令

项目存在对应脚本时，按需执行：

```bash
pnpm install
pnpm start
pnpm run build
```

如果当前阶段尚未具备运行条件，应在任务记录中说明原因，不能伪造验证结果。
